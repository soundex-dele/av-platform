# Windows → 浏览器传屏首版实施方案

日期：2026-10-26（Asia/Shanghai）。

状态：已进入实现。产品入口、运行说明见 [README.md](README.md)，实际验证记录见 [VALIDATION.md](VALIDATION.md)。下文保留原始实施要求，不作为验收通过声明。

## 1. 目标与交互

实现可信局域网内的一对一画面传输：

1. 浏览器打开独立传屏页面，点击“接收投屏”，显示一次性投屏码。
2. Windows 发送端选择显示器、输入投屏码，点击“开始传屏”。
3. 浏览器直接播放，无需接收者再次确认；支持全屏。发送端显示共享状态和本地预览。
4. 任一端停止即结束会话。再次传屏需生成新码。

默认最高 1080p、15 fps，保持比例、不放大小尺寸画面，优先文档演示的清晰度。首版不包含声音、窗口共享、远程控制、一对多和公网部署。

## 2. 现有基础与实现边界

现有 SDK 提供 Windows 主屏 GDI 采集、RTC 发布订阅、VP8 视频传输和本地预览基础；远控产品已有 ImGui／SDL2 桌面端、浏览器视频接收及 Go + SQLite 业务服务。传屏独立产品与配对流程尚未实现，指定显示器采集需要扩展。

遵循[目录结构与多业务边界](../../architecture/repository-layout.md)：传屏拥有独立客户端入口、业务模块、数据表和状态机，复用公共媒体能力，不复用远控输入授权模型。此前 RTC 验证中的失败和未验收项仍以[现状与交接记录](../rtc/STATUS_AND_HANDOFF.md)为准，本方案不表示它们已解决。

## 3. 实现内容

### 屏幕采集与 SDK

- 在现有公共媒体 API 中新增显示器枚举，返回屏幕 ID、名称、物理像素区域和主屏标记；为 `MediaSpec` 增加可选屏幕 ID，未指定时保持现有主屏行为。
- 扩展 Windows GDI 采集，支持副屏、负坐标和不同 DPI；合成当前屏幕内的鼠标指针。
- 按显示器比例计算偶数输出尺寸，横屏限制为 1920×1080，竖屏限制为 1080×1920。
- 复用现有 RTC、VP8 和本地预览链路，继续正确标记屏幕共享轨道；不新增传输协议或修改 SFU 架构。
- 传屏期间固定屏幕；屏幕移除或显示模式变化时停止并提示重新选择，不自动切换到其他屏幕。

### Windows 与 Web 客户端

- 在 `livekit-app/apps/screen-cast` 下新增独立 desktop、web 产品，沿用 C++20／ImGui／SDL2 和 TypeScript／Vite／livekit-client。
- 桌面端提供业务地址、显示器选择、投屏码、开始／停止、预览与错误提示；共享期间禁止修改屏幕。最小化继续共享，关闭窗口停止。
- 网页提供投屏码及有效期、等待／连接／播放／结束状态、全屏和停止按钮；收到实际视频帧后才显示正在播放。
- HTTP 和媒体操作放在后台，界面消费状态快照；取消连接和停止操作必须释放采集、媒体及工作线程。

### 配对与业务服务

- 新增独立 `screencast` 业务模块、SQLite 表和迁移，复用公共媒体客户端，不依赖远控授权模型。
- API 前缀为 `/api/v1/screen-cast/`：创建接收会话、兑换投屏码、查询状态、取得媒体连接信息、心跳和结束会话。
- 网页入口为 `/apps/screen-cast/`，业务进程新增 `-screen-cast-web` 参数，并保留现有远控入口。
- 投屏码使用随机 10 位数字、5 分钟有效、单次兑换；并发兑换只允许一个发送端成功。凭证区分发送与接收角色，只存哈希，限制创建和兑换频率。
- 每个会话建立独立双人房间：发送端仅发布，接收端仅订阅，双方均无数据发送权限；客户端不持有媒体服务密钥。

## 4. 生命周期与交付

- 状态为等待配对、已配对、传输中、已结束或已过期；配对后 30 秒内未完成双方连接则结束。
- 配对后双方每 3 秒发送心跳，失联期限为 30 秒。媒体断开、采集失败、主动停止或心跳超时均结束会话；首版不自动恢复共享。
- 本地停止优先终止采集与媒体，再通知服务；服务持久化结束状态并重试房间清理。服务重启终止旧会话。
- 新增独立 PowerShell 构建、启动脚本及运行文档，说明局域网地址、端口、依赖和故障排查。
- 仅抽取两产品确实共用的 HTTP、ImGui 构建等基础设施，保持远控行为兼容。

## 5. 验证与验收

以下均为后续实施要求，本次文档提交未运行功能验证。

- **Go 测试**：配对码过期与重复兑换、并发抢占、角色权限、心跳超时、幂等停止、重启清理、数据库迁移及业务路由隔离。
- **SDK／桌面测试**：模拟显示器枚举、负坐标、横竖屏缩放、屏幕消失、取消与重复启停；使用无窗口渲染检查各界面状态。
- **端到端测试**：真实业务服务和 C++ SFU、合成视频发送 fixture、无头 Chromium，验证配对、持续解码、停止、断线与不同会话隔离；失败时同样保存日志和结果。
- 回归现有远控、SDK 和媒体图相关检查，不降低已有断言。
- 方案整理时工作环境为 macOS，可执行适配该环境的 Go、Web 检查；Windows 原生编译、CTest 和完整媒体集成须在 Windows 环境执行，缺少环境时明确标记未验证。
- 实际多屏、DPI、鼠标显示、文档可读性和两机局域网效果单列人工验收。全过程不使用 computer-use 或桌面自动化，不将合成媒体测试表述为真实设备验收。

后续实现完成后，另行记录实际执行的命令、环境、结果和证据；自动化检查与实际设备人工验收分别报告。
